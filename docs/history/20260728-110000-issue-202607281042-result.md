### 1.1 content ブロックの正規化

`message.content` が文字列でない場合に本文だけを取り出す。`str` はそのまま通し（挙動を
変えない）、`list` / `dict` は `type` が `text` の part（または `type` を持たない part）の
`text` を順に連結する。`thoughtSignature` を持つ thought part は捨てる。

**1文字も取り出せなければ `LLMError` を投げる。** repr にフォールバックしない。
エラー文には part の `type` だけを載せ、本文は載せない（`thoughtSignature` を含みうるため）。
未知の content 形式に当たったとき、何を追加すればよいかがエラーから分かる。

境界（クライアント）で直した。`parse_answer()` 側で防御すると `answer_raw` は壊れたまま
残り、スクリーニングの判定経路にも同じ穴が残る。

### 1.2 quickstart の並べ替え

手順は 1〜15 に整理し、`validate → panel → screen → run` を本流にした。

- 手順6のジョブ定義を1本にまとめ、`panel.screener`（`mode: "ask"`）を持たせた。
  旧手順15の `ask`/`assume` 比較表と前提ブロックの説明はここへ移した。
- 手順9として `screen` を新設し、旧手順15の実行セルを移した。`build_panel()` の
  再実行は削った（手順8で済んでいる）。変数名は `job` / `run_result` に一本化。
- 割り付けセルを `M_20_40s` / `F_20_40s` に変更した。手順13のセグメント別集計で
  `sex` 軸が意味を持つようにするため（旧定義は男性のみで、`sex` 別に割ると片側が空だった）。

**並べ替えて初めて表に出た問題を1つ直した。** `ask` では手順8で引くのは候補なので、
`assigned_stimuli` はまだ空のまま表示される。旧構成では本流のジョブにスクリーナーが

手順9で確定後の割り当てを実際に表示するようにした。

## 3. 未対応事項

- **`model.thinking` がエンドポイントに送られていない。** `validate` で False を強制し
  `run_metadata.json` に記録するが、Databricks へのリクエストペイロードには載っていない。
  issue に貼られた `thoughtSignature` がその証拠。正しい抑止パラメータ名はエンドポイントと
  モデルで異なり、実機確認なしに実装すると「無視されるパラメータを送って対処済みという
  記録だけが増える」ため、`docs/issues/202607281100.md` に書き出して引き継いだ。
- **`type` が `text` 以外の text part は落とす。** OpenAI Responses API 系の
  `output_text` などには対応していない。実際に当たったら `LLMError` のメッセージに
  part の `type` が出るので、そこで追加すればよい。憶測で許容を広げると、thought part を
  本文に混ぜる危険のほうが大きい。
- ローカルで 125,000 行をノートブックから通すには Spark ドライバのヒープが既定（1GB）では
  足りず OOM する。Databricks 上では問題にならないため、ノートブックには手を入れていない。
