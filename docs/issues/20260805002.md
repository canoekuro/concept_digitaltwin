- 結果閲覧ページはクロス集計表だけにする。具体的には以下の構成にしたい。
  - 一番上に、購入意向の設問について、軸はコンセプト、セグメントは全体での、n数、各選択肢、Top2Box、平均値のクロス集計表
  - 2番目に、新規性の設問について、軸はコンセプト、セグメントは全体での、n数、各選択肢、Top2Box、平均値のクロス集計表
  - その下に属性別のクロス集計表（コンセプト・設問で選べるようにする。現状の「クロス集計表」のパートと同じ。ただ、コンセプト比較やパネル構成とインシデンスの選択肢は不要。あくまでコンセプト×2設問のみを選択肢にする）
- ダウンロードは、「集計表（Excel）とローデータ」のボタン1つのみでOK。集計表はコンセプト×セグメント（全体含む）のn数、各選択肢、Top2Box、平均値のクロス集計表のシート1枚のみにする。

## 確認結果（2026-08-05）

### 0. 起票文書が壊れていた

貼り付け事故で1〜7行目が重複していた（1〜3行目 = 4〜6行目、4行目が途中で切れて
1行目の末尾断片に接続、7行目が本来の完全版）。内容の欠落は無かったので、重複を
除去して上に置き直した。**要求そのものは変えていない。**

### 1. 一番上の2表は、既存のどの表でも作れない

| 既存 | 表側 | 表頭 |
|---|---|---|
| `crosstab_table()` | セグメント | 各選択肢・T2B・平均（コンセプト×設問ごとに1表） |
| `concept_summary_table()` | コンセプト | **T2B・平均のみ**（各選択肢の比率が無い） |

要求は「表側=コンセプト × 表頭=各選択肢＋T2B＋平均」で、どちらでもない。
ただし**集計の算術を書き足す必要は無い**。`result.crosstabs` は
コンセプト×設問ごとにセグメント行を持っているので、それを転置すれば作れる。
新しい整形関数 `concept_axis_table()` を `tables.py` に足し、値は
`compute_metric()` を通ったものだけを使う（CLI と UI で数字が食い違う余地を作らない）。

### 2. 属性別クロス集計の選択肢

現状の selectbox は `result.tables` を全件出しており、`crosstab_*` に加えて
`concept_summary` / `concept_summary_by_segment` / `panel_composition` が混ざっていた。
`crosstab_` 始まりに絞れば、指摘どおり「コンセプト×2設問のみ」になる。

### 3. ダウンロードを1ボタンにする

`st.download_button` は**1ファイルしか返せない**ので、「集計表とローデータ」を
1押しで渡すには同梱が要る。**xlsx 1ファイルの2シート構成**にした
（`集計表` / `ローデータ`）。ZIP も検討したが、受け取ってすぐ Excel で開ける方を採った。

`write_xlsx()` は CLI の `write_outputs()` と共用しているので、**これは変更していない**。
UI 都合で CLI の `report.xlsx` の中身が変わるのを避けるため、UI 専用の
`write_ui_workbook()` を別に足した。

### 4. 集計表シートに2問をどう収めるか

「シート1枚」に購入意向と新規性を入れるが、2問は選択肢ラベルが異なる。
**「設問」列を足して縦に積む**形にした。選択肢列は番号のみ（`選択肢1`〜`選択肢N`）に統一し、
ラベルは表の上の凡例行で設問ごとに示す。

### 5. `AGENTS.md` の不変条件との衝突を1点解消した

「シート1枚のみ」にすると、これまで概要シートに載せていた E3/E4 の注記
（品質フラグ率・割り付け外セルの混入）が消える。これは
**「パース失敗・拒否が閾値を超えたら必ず表面化させる」**（`SPEC.md` §11）に反する。
シートは増やさず、集計表シートの先頭に注記行として残した。

### 6. ローデータの指摘はそのとおり

`responses_query()` は `r.*` で引いており（`warehouse.py`）、`responses` のスキーマは
`stimulus_id` / `answer_codes` までで、コンセプト名も選択肢ラベルも持っていない。
両方とも `SurveyDefinition` から引けるので、`stimulus_name` と `answer_labels` を
列として足した。

**選択肢ラベルに直す前に `to_defined_codes()` で定義順へ戻している。**
`answer_codes` は**提示順**の番号なので、そのままラベルを引くと、選択肢をシャッフルした
設問で別の選択肢の名前が付く。今の2問は `randomize_options: false` なので実害は無いが、
飛ばすと将来壊れる。

あわせて `responses_query()` を `r.*` から明示列＋`to_json` に直した。配列カラムを
`to_json` して文字列で受け取るのは `warehouse.py` 自身が冒頭で決めている方針で、
このクエリだけ従っていなかった（コネクタが配列を何で返すかに挙動を預けていた）。

### 残る論点（この修正のスコープ外）

- **CLI の `responses_raw.csv` は据え置き。** 同じくコンセプト名も選択肢ラベルも
  持っていないが、今回の指摘は UI からのダウンロードについてなので、CLI 側の
  出力形式は変えていない。揃えるなら別途。
- **表示中の表の CSV ダウンロードは無くなった。** ボタン1つという要求に従ったため。
  画面の表は Excel の集計表シートに全件入っているので、内容としては失われていない。
