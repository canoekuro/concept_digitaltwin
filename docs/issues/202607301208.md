- surveyボリュームに格納する調査のyamlと、調査のconfigとしてのconfig/ui_config.yamlの2つがnotebookへの入力になっているが、modelなどの重複設定がある。そこで、UI上での設定と、ui_config.yamlの内容を結合したすべての情報が入ったyamlを生成し、それをsurveyボリュームに格納することとする。（notebook上で実行するときも、このyamlだけ編集すればよくなる）　※対応済み。
- ui_config.yamlについて、調査のデフォルト値と画面としての設定の2つが混在している。具体的には#0,#1,#2,#4が前者、#3,"5,#6,#7が後者。これを切り分けたい
  - # 0. この画面が作る調査の種類（SPEC_PHASE1.md §3.0）
  - # 1. 本調査（回答生成）のモデル設定。
  - # 2. プロンプト。
  - # 3. 設問フォームの初期値（購入意向・新規性）
  - # 4. スクリーニングの既定
  - # 5. 割り付けパターン（画面のラジオボタン）
  - # 6. 出力設定
  - # 7. 見積もり用の実績値
- ui_config.yamlに出力設定は不要？画面上で集計されるのであれば出力が不要なので。画面上での設定に必要であれば残す。
-  ui_config.yamlの「# 本調査でペルソナカードに含める定性フィールド」について、スクリーニングでは「include_attributes: true # 属性行（性別・年齢・居住地など）」「 include_summary: true    # ペルソナ総括文」が選べる。これを本調査側でも選べるようにしたい。また、属性行はもう少し細かく属性ごとに制御したい。
-  ui_config.yamlは全体的にスクリーニングと本調査に分かれているが、# 2. プロンプトにはスクリーニングと本調査の両方が含まれている。これは切り分けて、全体的にスクリーニングに関する設定→本調査に関する設定の流れとし、それぞれにモデル、プロンプト、ペルソナカード、その他の順で設定していくyamlとしたい。(ui_config.yamlだけではなく、surveyボリュームに置かれる調査定義も同様。)
