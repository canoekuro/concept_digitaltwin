## 1. やったこと

issue の7件すべてに対応した。

### 項目1: `job` → `survey` 全面リネーム（破壊的・`46bfa6b`）

永続列 `job_id` を `survey_id` に改称し、`JobDefinition` → `SurveyDefinition`、
`load_job` → `load_survey`、`run_job` → `run_survey`、`screen_job` → `screen_survey`、
調査定義のトップレベルキー `job:` → `survey:` まで含めて統一した。
`examples/job_sample.yaml` と `tests/test_job_loader.py` も改称。

旧 `job:` の調査定義は `RENAMED_TOP_LEVEL_KEYS` により、書き換え方とテーブル作り直しの
必要を添えて停止する。黙って読めてしまうと用語が二重に残るため。

`docs/history/` の過去ログは当時の記録として原文を保った。

### 項目2: `answer_code` の廃止（破壊的・`e0dc3f2`）

`responses` / `screener_responses` から `answer_code` を削除し `answer_codes` に一本化。
パース失敗は「選択式で `answer_codes` が空」で表す。判定は元から `codes` ベースだったので
挙動は変わらない。straightline 判定のみ `answer_codes[0]` ベースに書き換えた（対象は
選択式のみで1要素なので従来と同じ結果）。

### 項目3: プロンプトの config 化（`06e641b`）

`PromptConfig` に `system` / `headings` / `rules` を追加し、`prompt.py` のハードコードを
既定値に降格した。省略したキーは既定のまま残る。`rules.open` のみ `{max_length}` を
差し込め、解決できない差し込みは**読み込み時に停止**する（実行時まで気づけないため）。

上書きがあるのに `template_version` が既定のままなら `validate` が警告する
（`W_PROMPT_TEMPLATE_VERSION`）。同じ版で中身が違うと過去の結果と比較できなくなるため。

### 項目4: プロンプトの記録（`70fd1f5`）

実行後にセッション先頭の `[system]` / `[user]` を組み直し、
`outputs/{survey_id}/prompt_sample.md`（Markdown）と `run_metadata.json` に残す。
プロンプト組み立ては純関数なので、LLM を呼ばずに再構築しても送った内容と一致する。
記録するペルソナはセッションキー順で決めるため、何度実行しても同じ1名になる。

一致は推測ではなく、実際にエンドポイントへ渡ったメッセージを記録するテストで確認した
（`test_prompt_sample_matches_what_was_actually_sent`）。

### 項目5・6: notebook と `image_uri`（`3b1d040`）

- quickstart の調査定義に `prompt` を追加し、`answer_codes` に更新、`infer` を3方式目として
  説明、実行後に `prompt_sample.md` を表示するセルを追加した
- `image_uri` を Unity Catalog Volumes 前提に改め、`/Volumes/` 以外は警告する。
  DBFS のパスは旧形式として別の警告コードにした。`image_mode: native` は未実装として
  別途停止させるので、ここは警告に留めている

### 項目7: `infer` スクリーニング方式（`f0730d1`）

候補を `batch_size` 人ずつまとめて別セッションの LLM に渡し、条件合致の蓋然性が高い者に
だけ属性を付与する。判定本体は `persona_sim/panel/infer.py`。

パネル確定・`screened_out` の保持・`cell_rank` の振り直し・不足時の再試行は `ask` と同じ
経路を通す。作り直すと不変条件を二重に実装することになるため。

| | `ask` | `assume` | `infer` |
|---|---|---|---|
| 費用 | `size × oversample × 設問数` | 0 | `候補数 ÷ batch_size` |
| 属性付与 | 本人の回答 | 全候補に強制 | 蓋然性が高い候補のみ |
| インシデンス | 実測 | 測れない（null） | 推定値（別枠に記録） |

- 判定モデルは `infer.model` で部分指定でき、書かなかったキーは調査本体の `model` を
  引き継ぐ。`thinking` は指定させず常に OFF を強制する
- 判定に見せる情報は `include_attributes` / `include_summary` / `persona_fields` で絞る。
  既定は属性行と総括のみ
- 通過率は `screener_incidence_estimated` に分けて記録し、実測値の欄には入れない。
  判定結果には `inferred` フラグを立てる
- 判定条件（モデル・`batch_size`・見せた列）を実行メタデータに残す（§9.1）
