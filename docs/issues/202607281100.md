# `model.thinking` がエンドポイントに送られていない

`docs/issues/202607281042.md` の1件目（`answer_text` に content ブロックの repr が入る）を
調べる過程で見つけた別件。**修正はしていない。**

## 何が起きているか

`AGENTS.md` の不変条件に「思考モード（thinking）は常に OFF。回答が収束しペルソナ間の
ばらつきが失われる」とある。しかし `thinking` はジョブ定義のレベルでしか扱われておらず、
**推論エンドポイントへのリクエストには一切載っていない。**

- `persona_sim/panel/validate.py` — `model.thinking` が true ならエラーにする
- `persona_sim/metadata.py` — `run_metadata.json` に `thinking` を記録する
- `persona_sim/llm/databricks.py` — 組み立てる payload は `messages` / `temperature` /
  `max_tokens` / `response_format` のみ。**`thinking` に相当するものが無い**

つまり「思考モードを OFF にした」という記録だけが残り、モデル側は既定の挙動で動く。

## 根拠

`docs/issues/202607281042.md` に貼られた `databricks-gemini-3-5-flash-lite` の応答に
`thoughtSignature` が含まれていた。これはモデルが実際に思考した証拠である。
`thinking: False` を指定したジョブの実行結果としては、不変条件が守られていない。

```
[{'type': 'text', 'text': '普段、仕事や育児と介護で…', 'thoughtSignature': 'AY89a1/Gijbk…'}]
```

## 影響

不変条件の文言どおりなら、**ペルソナ間のばらつきが失われて結果の意味が変わる**。
現状これはどのフラグにも表れず、`run_metadata.json` はむしろ「thinking: false で回した」と
記録するので、後から見て気づけない。記録と実際の乖離という点が特に悪い。

## なぜ今回直さなかったか

思考を抑止するパラメータ名と受け付けられる値は、エンドポイントとモデルによって異なる。
実機で確認せずに実装すると、**モデルに無視されるパラメータを送って「対処済み」という
記録だけが増える**（今と同じ失敗を一段深いところで繰り返す）。

## 着手するときに決めること

- 対象エンドポイントで思考抑止に使えるパラメータを実機で確認する
  （送って無視されるだけなのか、エラーになるのか、本当に効くのか）
- 効かないモデルがあった場合の扱い。`validate` で止めるのか、警告にとどめるのか。
  少なくとも `thoughtSignature` 等の痕跡を検出したら品質フラグとして表面化させたい
  （`AGENTS.md`「パース失敗・拒否が閾値を超えたら、止めずに必ず表面化させる」と同じ考え方）
- `run_metadata.json` の `thinking` を「ジョブ定義の指定」ではなく
  「実際に抑止できたか」を表す形に変えるかどうか
