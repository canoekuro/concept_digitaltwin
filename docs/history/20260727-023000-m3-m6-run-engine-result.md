### 2. 実装

| モジュール | 内容 |
|---|---|
| `llm/client` | `LLMClient` プロトコル、`ChatMessage` / `Completion`、再試行可否を分けた例外 |
| `llm/databricks` | Model Serving 呼び出し。構造化出力のため OpenAI 互換 invocations を直接叩く。429・5xx は指数バックオフ＋ジッタ |
| `llm/fake` | 決定論的なダミー。プロンプトを読んで選択肢数を数え、ハッシュで回答を決める。拒否・パース不能・失敗を決定論的に注入できる |
| `run/prompt` | ペルソナカード・提示物・設問の組み立て、選択肢の決定論的シャッフルと `options_order` |
| `run/parsing` | 選択肢番号の抽出（全角・表記ゆれ対応）、拒否判定、構造化出力の JSON Schema |
| `run/session` | セッションの組み立てと逐次実行。`memory` の3値、リトライ、構造化出力のフォールバック |
| `run/executor` | スレッドプール、E5 判定、中断時の部分保存 |
| `run/flags` | 品質フラグ5種 |
| `run/run` | `panels` × `personas_base` 読み込み → 実行 → `responses` へ冪等 upsert、straightline の付け直し、E3/E4 警告 |
| `metadata` | `runs` テーブルと `run_metadata.json`（§9） |
| `storage/delta` | `merge_upsert`（MERGE）を追加。M5 でも使う |

`persona-sim run` を実装し、`--output-dir` を追加した。

### 3. 判断の記録

- **推論基盤は Databricks Model Serving。** サービス本体を Databricks Apps で提供する予定のため。
  認証は `databricks-sdk` の既定の認証チェーンに任せ、トークンもワークスペース URL も
  コードとジョブ定義に置かない
- **`azure_ai_foundry` は未実装として停止させる。** この環境から疎通確認できないため、
  動かないアダプタを黙って通すより明示的に止める
- **実行と再開の単位はセッション。** 途中まで進んだセッションは丸ごとやり直す。
  途中だけ埋めると `full_session` で履歴の欠けた回答が残り、再開前後で意味が変わる
- **`auto` のフォールバックは必ず記録する。** 黙って正規表現パースに落ちると、
  構造化出力を使っているつもりで精度が下がったことに気づけない

## 検証結果

### 単体テスト（Spark 不要）— 155 件すべて成功

プロンプト組み立て（§6.1 の順序、欠損列の省略、`persona_fields` の差し替え）、
パースの表記ゆれ（`3` / `３` / `3.` / `「3」` / `答え: 3` / `{"answer": 3}`）、
範囲外・拒否の判定、選択肢シャッフルと `options_order` の対応、
セッション粒度（`memory` の3値）、リトライとフラグ、構造化出力のフォールバック。

パース実装のレビューで、拒否パターン `お答えし(かねます|できません)` が
「お答えできません」を取りこぼす誤りを発見して修正した（活用が違うものを1つの括弧に
まとめると、存在しない「お答えしできません」しか一致しない）。

### Spark 結合テスト（`-m spark`）— 24 件すべて成功

M3・M6 の完了条件を直接検証している。

- **1コンセプト × 100人が完走**（M3 の完了条件）
- **中断→再開が完走時と一致**（M6 の完了条件）: 失敗を注入して途中で止めた状態から
  再実行し、一度で完走した結果と `answer_code` / `answer_raw` まで完全に一致することを確認
- 完走後の再実行で全セッションがスキップされ、行が二重にならない
- パース失敗のまま残った設問は再実行でやり直される
- 品質フラグ5種が立ち、**除外はされない**。E3・E4 の閾値超えが警告として出る
- straightline がペルソナ単位で、フラグの有無と実データが**両方向で一致**する
- E5 で中断しても完了分は保存され、同じコマンドで再開できる
- `responses` が §2.3 の列を順序どおり持つ
- `run_metadata.json` に §9 の項目が揃い、再現性の範囲が `inputs_only` と記録される

### 実データ検証（125,000 行 / 600人パネル、Fake エンドポイント）

`personas build` → `panel` → `run` を CLI から通した結果。

- `responses` が見積もりどおり **5,400 件**（600人 × 3案 × 3問）。5,400 セッション全て完了、失敗0
- 閉じた設問は 3,600 件（600人 × 6）、自由回答は 1,800 件。全ペルソナが6件ずつ回答している
- `run_metadata.json` に `source_dataset`（リビジョン付き）・`personas_base` の Delta バージョン・
  パネル構成・トークン数（入力 4,726,674 / 出力 90,436）・`reproducibility: inputs_only` が記録された
- `straightline` フラグは9行。これは**1ペルソナ × 9行**であり、実データを直接集計した
  「閉じた設問6問がすべて同じ位置のペルソナ = 1人」と一致する（フラグは行単位で立つ）
- 選択肢の分布は5択で均等（337〜377）。Fake クライアントに偏りが無いことも確認できた
