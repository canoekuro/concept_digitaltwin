# 男性のみを選んだのに結果に女性が混ざる問題の修正 — 計画

- **日付**: 2026/08/03 09:00
- **起票**: 「男性を選んだのに女性対象のアンケートになった」（結果閲覧の集計表・ローデータで発覚）

## 調査結果

**性別の絞り込み自体は正しく動いていた。** `sex_ranges={"男": (20,69)}` で
`build_survey_dict()` を実行して確認した。

- `panel.filters` → `{sex: 男, age_min: 20, age_max: 69}`
- `panel.quotas.cells` → `M_20_29`〜`M_60_69` の5セルのみ（すべて `sex: 男`）

`persona_sim/panel/sampling.py` の `select_members()` がこの両方を Spark 述語として
適用しており、UI → 調査定義 → パネル抽出 → プロンプトの経路に性別の取り違えは無い。

真因は `survey_id` の食い違いだった。`app/views/survey_design.py` は
`build_survey_dict()` を3回呼ぶが、`persona_sim/uiconfig/build.py` は
`form.survey_id` が未指定（UI からは常に未指定）だと呼ぶたびに現在時刻から
ID を作り直す。

| 箇所 | ID | 用途 |
|---|---|---|
| `build_survey()` | A | 画面表示 / YAML のファイル名 / 冪等トークン |
| `build_survey_dict()`（投入） | B | YAML の中身。**ジョブが結果を書き込む ID** |
| `build_survey_dict()`（表示） | C | 「組み立てた調査定義を見る」 |

再現した実測値:

```
L169 survey.survey_id : survey_20260803083613   ← 画面が「開始しました」と表示する ID
L205 YAML の survey.id : survey_20260803083614   ← runs / panels / responses に入る ID
```

結果、画面が案内した ID は結果テーブルのどこにも存在しない。結果閲覧の一覧ラベルは
`調査名（完了時刻）` だけで同名の別実行を見分けられず、結果画面には対象者の表示も無いため、
別の調査（男女混在）の集計表を自分の調査として読むことになる。
冪等トークンも毎回変わるため、docstring が謳う二重投入の防止も効いていなかった。

## 方針

「同じ調査定義から2つの ID が生えうる」状態を構造的に無くす。あわせて対象者を画面に出し、
定義と実データの食い違いを集計時に表面化させる。

1. `survey_id` を投入1回につき1つに固定する（`session_state` に持ち、組み立ては1回だけ）
2. 投入先パスと冪等トークンを**調査定義の中身**から引く（別経路の ID を受け取らない）
3. `survey_id` にランダム識別子を足し、同一秒・同名の衝突を防ぐ
4. 対象者を調査設計・結果閲覧の両方に出す。結果一覧のラベルに `survey_id` を添える
5. 割り付けセルに無い属性値が集計対象にあれば `notes` に出す（止めない）

## スコープ外

- `_global_filters()` が複数性別のとき `sex` を落とす件は `docs/SPEC_UI.md` §3.3 どおりの
  意図した挙動。セル条件が性別を担保しており、男性限定になることを実行して確認済み。
- 両性別が初期状態でチェック済みである点は今回の原因ではない（利用者はチェックを外している）。
  対象サマリーが入れば外し忘れも投入前に気づける。
