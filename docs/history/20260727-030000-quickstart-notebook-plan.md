## 目的

M1〜M3・M6 が揃い、CLI からはジョブ定義 → 回答生成まで通るようになった。しかし
**利用側が最初に触る入口が無い**。CLI の引数と環境変数を README から拾って組み立てる必要があり、
Databricks 上でどう動かすかも書かれていない。

環境セットアップから結果までを1本で通すノートブックを用意する。
`SPEC.md` §10.2「Databricks ノートブックから同じ関数群を呼べること。
ジョブ定義を dict で渡せるようにする」への対応でもある。

## 設計判断

- **既定は `model.endpoint: fake`。** 推論エンドポイントが無くても最後まで通せるようにする。
  実エンドポイントへの切り替え手順はノートブック内に書き、「最初は10人規模で試す」と添える
- **簡易集計では `answer_code` を `options_order` で定義順に戻してから集計する。**
  この読み替えを省いた例を載せると、選択肢をシャッフルした設問で結果の意味が変わる
  実装を教えてしまう
- **統計的推測の語彙（p値・有意差・信頼区間）は使わない**（`AGENTS.md` 禁止事項）。
  コンセプト間の相対比較として読む旨を書く
- **CC BY 4.0 の帰属表示と出力の注記を冒頭と末尾に置く**（`SPEC.md` §15.3）
- ノートブックは **出力を含めずにコミットする**。差分が読めなくなり、古い結果が残るため
